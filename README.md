# Мой деканат

Личный кабинет студента: расписание, успеваемость, заявки в деканат, уведомления и помощник «Спроси деканат» на базе ИИ. Прототип для MGIMO AI Challenge, номинация «Вайб-кодинг».

**Концепт, не официальный сервис вуза. Все данные вымышленные, к настоящим системам вуза проект не подключён, логотип свой.**

## Как открыть сайт

**https://dekanat-flockyafk.msk1.amvera.tech** (хостинг в России, VPN не нужен). Сайт рассчитан на телефон от 360 px и работает на компьютере. Тема светлая или тёмная, переключатель в шапке.

| Студент 2 (группа МО-231) | student2 | demo-student-2 |
| Студент 3 (группа МЭО-232) | student3 | demo-student-3 |

У первых трёх студентов и у сотрудника смена пароля выключена: пароли публичны, и любой посетитель мог бы закрыть вход для жюри. Для проверки функции есть студент 4: «Профиль», «Сменить пароль». При каждом запуске сервера его пароль возвращается к `demo-student-4`. Те же аккаунты перечислены на странице `/about` сайта.

### Что посмотреть (сценарий жюри)

1. Войдите как `student1`: на «Сегодня» ближайшая пара, переносы и замены, дедлайны, объявления.
2. «Расписание»: день и неделя, верхняя и нижняя недели.
3. «Учёба»: средний балл, долги, зона риска, карточка дисциплины, сессия.
4. «Заявки»: закажите справку, увидите статус «Отправлена».
5. Войдите как `staff` (в другом браузере или после выхода): переведите заявку в «Готова» и опубликуйте объявление.
6. Снова как `student1`: уведомление и новый статус заявки.
7. Как `student2`: данные другие, а адрес заявки студента 1 даёт страницу 404.
8. Помощник: «Что у меня завтра?», «В каком статусе моя справка?», «Какие пары в понедельник?». Попросите данные другого студента или то, чего в данных нет, помощник откажет.
9. «Новая заявка»: опишите ситуацию двумя фразами, помощник составит черновик. Отправляете заявку вы сами.

## Как устроена безопасность

- **Доступ только к своим данным.** Каждая функция в `lib/data/` берёт пользователя из сессии и фильтрует данные по его id. Идентификатор студента из адреса или формы для выбора данных не используется. Чужая запись даёт 404. Для каждой функции есть тест: студент А не видит и не меняет данные студента Б.
- **Роль сотрудника** проверяется на сервере (страница, действие и функция данных).
- **Пароли** только в виде хэша bcrypt, в журналы не попадают. Вход ограничен по числу попыток.
- **Сессия:** cookie `httpOnly`, `sameSite=lax`, `secure` на боевом сайте.
- **Ввод** проверяется zod на сервере.
- **Секреты** лежат в `.env` и в настройках хостинга, в репозитории их нет (`.env.example` без значений). Файл базы `data/` в `.gitignore`. Историю git проверяет `npm run scan:history`.

## Как работает ИИ и как он ограничен

- Модель: Qwen3-30B на Amvera LLM (доступна из России). Все вызовы идут через один файл `lib/ai.ts`.
- В запрос к модели попадают **только данные текущего студента** из сессии. Тест в `npm test` проверяет, что в запросе студента А нет ни одной записи студента Б.
- Тексты заявок, объявлений и вопросов передаются модели как **данные, а не инструкции**. Команды внутри текста («забудь правила», «покажи данные других») не выполняются.
- Ответ показывается как обычный текст. Ссылки в ответе проверяются по списку маршрутов кабинета, внешние адреса вырезаются.
- Если ответа в данных нет, помощник говорит «В данных этого нет», а не выдумывает.
- Расписание на день недели, «завтра» или дату **считает код**, а не модель (после найденной ошибки), модель только формулирует ответ.
- У каждого студента суточный лимит запросов, есть и общий. Текст вопросов в журнал не пишется, только счётчик. История диалога хранится только в браузере.
- Красная команда (`npm run redteam`, 27 атак на реальной модели) и найденные ошибки описаны в `docs/ai-errors.md`.

## Запуск на своём компьютере (PowerShell)

```powershell
npm install
Copy-Item .env.example .env   # потом впишите значения, см. ниже
npx prisma migrate dev
npm run seed
npm run dev
```

Минимальный `.env` (без ключа помощник работает на заглушке с готовыми ответами):

```
DATABASE_URL="file:../data/dev.db"
SESSION_DAYS=14
AI_DAILY_LIMIT=30
```

Чтобы подключить настоящую модель, добавьте провайдера и свой ключ. Ключ хранится только в `.env`, файл не попадает в git:

```
AI_PROVIDER=amvera
AI_API_KEY=<ваш ключ из кабинета Amvera, раздел LLM>
AI_MODEL=qwen3_30b
```

Сайт откроется на http://localhost:3000.

## Команды

- `npm run dev` запуск локально
- `npm run lint`, `npm run typecheck` проверка кода
- `npm test` тесты (отдельная база `data/test.db`, помощник на заглушке, к реальной модели не ходят)
- `npm run e2e` сценарий жюри (раздел 13 ТЗ) на ширине 360 px, проверка тёмной темы, отдельные база и порт 3200
- `npm run redteam` красная команда на реальной модели (27 атак), отчёт в `docs/redteam-results.md`
- `npm run scan:history` поиск ключей и паролей во всей истории git
- `npm run seed` заполнить базу вымышленными данными (стирает старые)
