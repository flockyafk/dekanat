# Деплой на Amvera

**Адрес сайта:** https://dekanat-flockyafk.msk1.amvera.tech
Статус на 11 ноября: сайт открывается без VPN, вход работает с компьютера и с телефона (проверил человек).
Обновление сайта: `git push amvera main:master`.

Что настроено в репозитории:
- `Dockerfile`: сборка Next.js, Prisma, запуск через `docker-entrypoint.sh`.
- `amvera.yaml`: `persistenceMount: /data` (постоянное хранилище), `containerPort: 8080`.
- База SQLite: `file:/data/dekanat.db`. Путь абсолютный и вписан в Dockerfile, поэтому база переживает пересборку. Папка `data` внутри приложения (`/app/data`) это другое место, она не постоянная.
- При каждом старте контейнера: `prisma migrate deploy`, затем сид. Сид в production работает только на пустой базе, поэтому перезапуск не стирает заявки.
- Переменные окружения на этапе сборки недоступны, поэтому нужные значения вписаны в Dockerfile. В интерфейсе Amvera вносить ничего обязательного не нужно. Необязательные: `SESSION_DAYS`, `AI_DAILY_LIMIT`.

Источник: документация Amvera (docs.amvera.ru): разделы про Docker, хранилище /data, переменные, тарифы.

## Реальная модель на Amvera (11 ноября)

Помощник и черновик заявки работают через Amvera LLM Inference (формат OpenAI `chat/completions`): адрес `https://inference.waw0.amvera.ru/v1`, заголовок `Authorization: Bearer <токен>`, модель `qwen3_30b` (Qwen3-30B). Токен берётся в личном кабинете Amvera: раздел «LLM», страница модели.

Переменные проекта на Amvera (раздел «Переменные», после добавления перезапустить контейнер; на этапе сборки они недоступны, а нужны только при работе, так что это нормально):

| Переменная | Значение | Тип |
|---|---|---|
| `AI_PROVIDER` | `amvera` | переменная |
| `AI_API_KEY` | токен из кабинета | **секрет** |
| `AI_MODEL` | `qwen3_30b` (не `qwen3-30b-instruct`: такое имя API не принимает) | переменная |
| `AI_DAILY_LIMIT` | `15` (вопросов на студента в сутки; по умолчанию 30) | переменная |
| `AI_TOTAL_DAILY_LIMIT` | `150` (всего в сутки на всех; по умолчанию 200) | переменная |

Расход токенов: один запрос это примерно 2-3 тысячи токенов (данные студента и инструкции плюс короткий ответ). Пакет 1 млн токенов в месяц это порядка 300-400 запросов. Тестовые аккаунты публичны, поэтому есть общий суточный предел: когда он исчерпан, студент видит понятное сообщение, остальной кабинет работает. Если провайдер недоступен, ключ не задан или кончились токены, помощник отвечает «недоступен» и ничего больше не ломается.

Ключ хранится только в `.env` (в `.gitignore`) на компьютере и в секретах проекта на Amvera. В git его нет: автотест `tests/ai-boundary.test.ts` проверяет это при каждом `npm test`.

## Решение: смена пароля у тестовых аккаунтов выключена (11 ноября)
Аккаунты `student1`, `student2`, `student3` и `staff` указаны в README и на странице `/about`, их пароли публичны. Сайт открыт для всех, поэтому любой посетитель мог бы войти под тестовым аккаунтом, сменить пароль и закрыть вход жюри. Поэтому для этих четырёх логинов форма смены пароля отвечает: «В демо-версии пароль тестовых аккаунтов менять нельзя». Для остальных пользователей смена пароля работает полностью (проверка текущего пароля, не короче 8 символов, закрытие других сессий, лимит попыток), это проверено автотестом.
Решение принял автор проекта. Пятый аккаунт `student4` без блокировки, на котором жюри может проверить смену пароля, сделан 13 ноября (пароль возвращается к демо-значению при каждом старте контейнера). Блокировка снимается переменной окружения `DEMO_LOCK=0`.
Это сознательное отклонение от буквы ТЗ (раздел 4.1): функция есть, но на публичных демо-аккаунтах отключена ради сохранности доступа для жюри.

## Известные риски
- Лимит попыток входа привязан к логину. Посторонний может «заблокировать» чужой логин на 15 минут. Для конкурсного прототипа риск принят. Запись по `security-reviewer`, шаг 1.
- Dockerfile не собирался локально (Docker не установлен). Первая проверка сборки произойдёт на Amvera.
