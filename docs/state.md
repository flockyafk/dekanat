# Состояние проекта

**Сайт:** https://dekanat-flockyafk.msk1.amvera.tech (Amvera, открывается без VPN, вход работает с компьютера и телефона по проверке человека, скриншот `docs/screens/03-deployed-today-mobile.png`). Из среды разработки сайт не открывается (соединение закрывается), поэтому проверки на живом сайте делает человек.

Обновлено: 17 ноября 2026. **Готово по плану: шаги 1 и 2, «Сегодня» и профиль, расписание (13), успеваемость и сессия (14), заявки и уведомления (15), кабинет сотрудника и помощник на заглушке (16), реальная модель, черновик заявки, красная команда и `npm run e2e` (17).** Новые версии лежат в коммитах, на Amvera ещё не выложены. Чтобы реальная модель заработала на сайте: `git push amvera main:master` и внести переменные проекта (список в `docs/deploy-amvera.md`; без ключа помощник отвечает «недоступен», остальной кабинет работает). Сценарий жюри на развёрнутом сайте с телефона делает человек после пуша. Дальше по плану: 18 ноября телефон от 360 px, состояния загрузки, пустоты и ошибки. Недели считаются по номеру недели ISO (нечётная верхняя), это допущение прототипа; реальная привязка к учебному календарю вуза не делалась.

## Готово
- Репозиторий, каркас Next.js 15 + TypeScript strict + Tailwind 4, схема SQLite (Prisma 6), миграция `init`, сид, вход и выход.
- Деплой на Amvera: `Dockerfile`, `amvera.yaml`, база в `/data`, миграции и сид при старте, заголовки безопасности. Подробно в `docs/deploy-amvera.md`.
- Каркас кабинета: шапка с колокольчиком и счётчиком непрочитанных, нижняя панель на телефоне, боковая на компьютере (пять пунктов из ТЗ), загрузка (скелетон) и ошибка (`app/(app)/(lists)/loading.tsx`, `app/(app)/error.tsx`). Правило: страницы-списки лежат в группе `(lists)` (с экраном загрузки), страницы-карточки по id в группе `(details)` (без него), иначе чужой адрес даёт страницу 404 с кодом 200. Так же делать `/requests/[id]`.
- Экран «Сегодня» (раздел 3 ТЗ): следующая пара с минутами до начала, изменения на сегодня (цветом), дедлайны и заявки с новым статусом, сводка (средний балл, долги, ближайший экзамен), три объявления, поле «Спроси деканат» с примерами. Пустые состояния у каждого блока.
- Расписание `/schedule` (раздел 4.2, 13 ноября): вид «День» (вкладки, свайп) и «Неделя», верхняя и нижняя недели, карточка пары, перенос, замена аудитории и отмена видны на карточке и на «Сегодня», пустое состояние «Сегодня пар нет». Заглушка `/schedule` убрана. Всего 26 тестов.
- Успеваемость `/grades` и `/grades/[courseId]` (раздел 4.3, 14 ноября): сводка «как у меня дела» (средний балл, долги, зона риска), дисциплины семестра с баллом и формой контроля, карточка дисциплины (оценки по работам, посещаемость, преподаватель, зачёт или экзамен), блок «Сессия» (даты, результаты, долги). Зона риска: балл ниже 60, посещаемость ниже 70% или долг. Добавлена таблица `Attendance` (дополнение к модели ТЗ). Чужая дисциплина даёт настоящий 404. Всего 36 тестов.
- Заявки `/requests`, `/requests/new`, `/requests/[id]` (раздел 4.4, 15 ноября): каталог из пяти видов, форма из двух полей с проверкой, список со статусами, страница заявки с историей и комментарием деканата, суточный лимит 10 заявок. Функция смены статуса сотрудником с уведомлением студенту готова и покрыта тестами (`lib/data/staff.ts`), экран сотрудника 16 ноября.
- Уведомления `/notifications` (раздел 4.5): лента, адресация всем, группе или студенту, счётчик на колокольчике, «Прочитано» и «Отметить всё прочитанным». Ссылки показываются только из фиксированного списка маршрутов (`lib/routes.ts`, тот же список понадобится помощнику).
- Русский экран 404; код ответа 404 для чужих и несуществующих записей проверен в браузере. Всего 51 тест. ТЗ, раздел 8, дополнен таблицами `Attendance` и `LoginAttempt`.
- Кабинет сотрудника `/staff` (раздел 5.1, 16 ноября): заявки всех студентов с фильтром, смена статуса с комментарием и уведомлением, публикация объявления всем или группе. Роль проверяется на странице, в действии и в функции данных; студент получает настоящий 404.
- Помощник «Спроси деканат» (раздел 4.6): `lib/ai.ts` единственное место вызова ИИ. Провайдеры: заглушка с готовыми ответами (по умолчанию, для тестов) и **Amvera LLM, модель Qwen3-30B (`qwen3_30b`)**, формат OpenAI chat/completions, настройки `AI_PROVIDER`, `AI_API_KEY`, `AI_MODEL`, `AI_BASE_URL`, `AI_TIMEOUT_MS`. Таймаут 30 с, понятное сообщение при недоступности, адрес только по HTTPS, без перенаправлений. Поле на «Сегодня» и диалог `/assistant`, вопрос уходит POST. Контекст только из данных текущего студента (обязательный тест в `npm test`), ссылки только из списка маршрутов и только свои id (если модель забыла ссылку, сервер добавляет её по теме вопроса), внешние адреса вырезаются из ответа, суточный лимит на студента 30 (`AI_DAILY_LIMIT`) и общий суточный предел 200 (`AI_TOTAL_DAILY_LIMIT`, защита пакета 1 млн токенов), текст вопросов не хранится и не пишется в журнал. Промпты: помощник v2, черновик v3 (`docs/prompts/assistant-system-v2.md`). Всего 118 тестов, в том числе `tests/ai-boundary.test.ts` (ИИ только через `lib/ai.ts`, ключа нет в git) и `tests/ai-provider.test.ts` (запрос, ошибки, таймаут; без сети). Ограничение: очередь по студенту для лимитов (заявки, ИИ) рассчитана на один экземпляр сервера; при нескольких экземплярах перенести резерв лимита в атомарный запрос к базе.
- Черновик заявки (раздел 4.6, 17 ноября): на `/requests/new` студент описывает ситуацию двумя фразами, помощник предлагает вид и текст заявления, текст подставляется в форму, студент правит и отправляет сам, автоматической отправки нет. Не выдумывает факты (пропуски в [скобках]), делит лимит с помощником.
- Красная команда на реальной модели (`npm run redteam`, 27 атак): 3 прогона, итог OK 25, ПРОВЕРИТЬ 2, ОШИБКА 0; найденные ошибки и исправления в `docs/ai-errors.md` (раздел «Ошибки помощника»), отчёты `docs/redteam-results*.md`. Вывод: Qwen3-30B подходит, замена на DeepSeek-V3 не нужна.
- `npm run e2e` (Playwright, 360 px, отдельные база и порт): сценарий жюри из раздела 13 ТЗ, 10 из 10 на заглушке и 10 из 10 с реальной моделью (шаги 10–12).
- На «Сегодня» показываются и ближайшие изменения расписания (в выходной «изменений на сегодня» нет, а перенос должен быть виден).
- Профиль (раздел 4.1): ФИО, факультет, направление, курс, группа, зачётка, почта, смена пароля (zod, проверка текущего пароля, закрытие других сессий), выход.
- Время считается по Москве (`lib/time.ts`), чётность недели по номеру недели ISO (нечётная верхняя).
- Демо-даты (замена аудитории сегодня, отмена завтра, перенос послезавтра, дедлайны) пересоздаются при каждом старте контейнера (`prisma/refresh-demo.ts`), поэтому у жюри в день проверки в расписании всегда есть изменения. Пользователей, заявки и оценки это не трогает.
- Расписание в сиде: у группы 1 и группы 2 разные пары на понедельник-пятницу.
- Тесты: 17 штук на отдельной базе `data/test.db` (вход, лимит попыток с параллельным перебором, роль, изоляция данных «Сегодня», расписания, уведомлений, смена пароля, время по Москве).
- `lint`, `typecheck`, `test`, `build` проходят. Playwright установлен, экран «Сегодня» проверен на 360 px (горизонтальной прокрутки нет, области нажатия от 44 px).

## Заглушки (будут позже по плану)
- Реальная модель проверена локально; на сайте Amvera заработает после пуша и внесения переменных (человек).
- Остаток по качеству: в черновике иногда остаётся фраза «в связи с личными обстоятельствами», хотя студент причину не назвал (модель добавляет, пропуск [укажите причину] тоже ставит); студент правит текст сам. Модель пересказывает дословно команды из комментариев и объявлений как цитаты, не выполняя их.
- `refresh-demo.ts` стирает все переносы пар и дедлайны при старте контейнера. Сотрудник пока создаёт только объявления (они не затрагиваются). Если добавим создание переносов и дедлайнов сотрудником, исключить их из очистки.
- Кабинет сотрудника без отдельной страницы заявки и без публикации ссылок в объявлениях (поле `link` у уведомлений создаётся только системой).
- shadcn/ui не подключён: компоненты написаны на Tailwind своей темы (`components/ui.tsx`). Подключим, если понадобится.
- `security-reviewer` как именной субагент в сессии не виден; проверки выполняет агент general-purpose по его инструкциям.

## Открытые вопросы к человеку
1. В локальном `.env` исправить `AI_MODEL=qwen3-30b-instruct` на `AI_MODEL=qwen3_30b` (первое имя API не принимает, ответ HTTP 400).
2. Внести переменные проекта на Amvera (список в `docs/deploy-amvera.md`; `AI_API_KEY` как секрет) и выложить версию: `git push amvera main:master`.
3. Пройти сценарий жюри на развёрнутом сайте с телефона и сделать скриншоты в `docs/screens/` (особенно `/assistant`, `/requests/new` с черновиком, `/staff`).
4. Опрос однокурсников идёт параллельно.
